Select text in a native assistant message to show floating Reply and New chat options. No extra buttons appear beneath messages. Paseo retains its native message rendering, copy controls, and Fork chat from here menu.

Reply opens an editable quote and reply form for the same agent. Enter sends, Shift+Enter adds a newline, and IME composition does not send. Running agents use steer behavior, which Paseo may implement by restarting the turn. Failed sends preserve the draft; check the chat before retrying an uncertain send.

New chat opens a reply form, then creates and opens a chat containing earlier messages and concise tool summaries through the selected response, plus your quoted reply. Context is capped at 100,000 characters with omission markers. Workspace files are shared; visible provider/model/mode/thinking/features are copied. Hidden provider state, custom prompts, tool policies, per-agent MCP configuration, and subagent logs are not copied. Uncertain creation blocks resubmission; Open chat retries navigation without creating another agent.

Requires Paseo 0.14.0 or later 0.x desktop/web (reviewed on 0.14.0, 0.15.0, and 0.15.1). The selection popup uses an invisible composer contribution and a version-specific DOM adapter; ambiguous pane ownership is rejected. This may leave native composer-track spacing. Native mobile and archived chats do not receive the popup. The plugin adds no backend or separate external service. Submitted quotes, replies, and new-chat history pass through Paseo to the configured model provider; normal provider permissions, costs, and retention apply. Drafts are held in memory and are not durable across navigation or reload.
